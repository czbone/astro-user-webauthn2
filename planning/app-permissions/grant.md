# 利用許可

本ファイルでは、認証サーバーと参加アプリが共有する利用許可の仕様を定めます。利用許可は、その参加アプリに入れるかどうかだけを表します。業務ロールは各参加アプリが持ち、ここには書きません。

認証サーバーは参加アプリへの引き渡し可否を判定するときにこの実効許可を使い、参加アプリは各リクエストの入場可否を判定するときに同じ手順を使います。両者の手順を別々に実装・変更してはいけません。認証サーバー自身の画面と API は対象外であり、`AppGrant` を要求しません。

共通ロール `admin` や `manager` であっても、利用許可がなければ参加アプリへ引き渡しません。入場後の管理操作とアプリ内ロール管理は、参加アプリが `User.role` を読み取って判定します。

## データ

`App.defaultPermission` は NULL を許容します。既定なしは SQL `NULL` で表します。空文字列は有効な値ではありません。

`AppGrant.userId` は必須で、一意制約は `(userId, appId)` です。利用者とアプリの各組み合わせにつき、行は1件だけです。全利用者分の行は作成しません。

| 列 | 内容 |
| --- | --- |
| `App.defaultPermission` | `NULL`、または `allow`。`NULL` の場合、`AppGrant` の行がある利用者だけが入れる |
| `AppGrant.permission` | `allow`、または `none` |

`none` は許可ではありません。その利用者だけを拒否する値です。既定には書きません。

## 実効許可

実効許可の判定には `userId` と `appId` を渡します。結果は `allow`、または付与なしです。判定には `User.role` を使いません。

```text
App がない
  → 付与なし
AppGrant がある
  → permission が allow なら allow
  → none、空文字列、allow 以外なら付与なし
    既定の判定には進まない
AppGrant がなく、defaultPermission が allow
  → allow
それ以外
  → 付与なし
```

例外行がある場合は、その行を既定値より優先します。`permission` が `none` または有効値以外であれば、既定値は適用せず、付与なしとします。

## セッション

Redis のセッション値には、利用許可も `User.role` も格納しません。既定の変更や行の追加・変更・削除は、次回のリクエストから反映されます。セッションを作り直す必要はありません。

付与なしのときは、セッションの有効期限（TTL）を延長しません。

## 例

| 既定 | 行 | 実効許可 |
| --- | --- | --- |
| `allow` | なし | `allow` |
| `allow` | `none` | 付与なし |
| `NULL` | なし | 付与なし |
| `NULL` | `allow` | `allow` |
| `allow` | 一覧にない文字列 | 付与なし |
| `admin` や `user` | なし | 付与なし |

## 必須事項

- 実効許可の手順は、引き渡しと参加アプリで同じにする
- 全利用者分の `AppGrant` は作成しない
- `userId` が空の `AppGrant` は作らない
- `NULL` を既定なしとして保存し、空文字列や `none` を既定に書かない
- `allow` 以外の文字列は、行にあっても既定にあっても付与なしにする
- 入場の可否に `User.role` を使わない
