# 利用権限

本ファイルでは、認証サーバーと参加アプリが共有する利用権限の仕様を定めます。認証サーバーは参加アプリへの引き渡し可否を判定するときにこの実効権限を使い、参加アプリは各リクエストのアクセス可否を判定するときに同じ手順を使います。両者の手順を別々に実装・変更してはいけません。認証サーバー自身の画面と API は対象外であり、管理操作は `User.role` で認可します。

## データ

`App` に NULL を許容する `defaultPermission` を追加します。既定なしは SQL `NULL` で表します。空文字列は有効な値ではありません。

`AppGrant` は現在の仕様を維持します。`userId` は必須で、一意制約は `(userId, appId)` です。利用者とアプリの組み合わせごとに、行は1件だけです。

| 列 | 内容 |
| --- | --- |
| `App.defaultPermission` | `NULL`、または正の権限の一つ。`NULL` のアプリは、行がある利用者だけがアクセスできる |
| `AppGrant.permission` | 正の権限の一つ、または `none` |

`none` は順位のある権限ではありません。その利用者だけを拒否する値です。既定には書きません。

行がない場合、既定があるアプリでは既定を使い、既定が `NULL` のアプリではアクセスを許可しません。

## 正の権限

正の権限は名前の一覧です。現在の一覧は `admin` と `user` です。`admin` が最上位です。

権限名を追加するときは、この一覧と、各参加アプリでアクセスを許可する画面を同じ変更で更新します。列の型は変えません。一覧にない文字列は正の権限ではありません。

| 値 | 位置 |
| --- | --- |
| `admin` | 最上位。下位の権限で許可された画面にもアクセスできる |
| `user` | `admin` より下位 |
| 追加する名前 | 追加するときに、`admin` より下の位置と、アクセスを許可する画面を定める |
| `none` | 権限ではない。`AppGrant` だけに書く |

下位の権限同士の包含関係は、権限名を追加するときに定めます。アクセスが明示的に許可されていない画面は開けません。

## 実効権限

実効権限の判定には `userId` と `appId` を渡します。結果は、正の権限の一つ、または付与なしです。判定には `User.role` を使いません。

```text
App がない
  → 付与なし
AppGrant がある
  → permission が正の権限なら、その値
  → none、空文字列、一覧にない文字列なら、付与なし
    既定へは進まない
AppGrant がなく、defaultPermission が正の権限
  → その値
それ以外
  → 付与なし
```

例外行は既定を置き換えます。既定より高い値、低い値、`none` のいずれであっても、行の値をそのまま使います。既定と行を比較して、より高い方を採用することはありません。

`User.role` が `admin` でも、実効権限は上記の結果です。既定が `user` で行がない利用者は、認証サーバー上の管理者でも参加アプリでは `user` です。

`User.role` は、認証サーバー自身の管理機能の認可にだけ使います。通常の認証操作はログイン状態とパスキー状態で判定します。認証サーバー自身へのアクセス判定は本手順の対象外であり、`AppGrant` を要求しません。一方、認証サーバーが参加アプリへの引き渡しを行う際は、本手順で対象アプリの実効権限を決めます。

## セッション

Redis のセッション値には、権限も `User.role` も格納しません。既定の変更や行の追加・変更・削除は、次回のリクエストから反映されます。セッションを作り直す必要はありません。

付与なしのときはセッションの TTL を延ばしません。

## 例

| 既定 | 行 | 実効権限 |
| --- | --- | --- |
| `user` | なし | `user` |
| `user` | `admin` | `admin` |
| `user` | `none` | 付与なし |
| `NULL` | なし | 付与なし |
| `NULL` | `user` | `user` |
| `user` | 一覧にない文字列 | 付与なし |
| 一覧にない文字列 | なし | 付与なし |
| `admin` | なし | `admin` |

最後の例では、パスキーを登録済みの利用者がそのアプリの管理者になり、付与一覧にもアクセスできます。

## 必須事項

- 実効権限の手順は、引き渡しと参加アプリで同じにする
- 利用者全員の `AppGrant` は作らない
- `userId` が空の `AppGrant` は作らない
- `NULL` を既定なしとして保存し、空文字列や `none` を既定に書かない
- 一覧にない文字列は、行にあっても既定にあっても付与なしにする
- 参加アプリの画面・APIへのアクセス許可に `User.role` を使わない
- `admin` は、下位の権限で許可された画面にもアクセスできる
