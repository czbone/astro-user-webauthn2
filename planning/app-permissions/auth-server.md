# 認証サーバー

本ファイルは、利用権限について認証サーバーが行うことです。実効権限は [grant.md](grant.md) の手順だけを使います。ログイン、パスキー、招待、ユーザー作成は今のとおりです。認証サーバーは投稿などの業務機能を持たず、`Post` API、画面、データモデルを廃止します。

## スキーマ

認証サーバーがマイグレーションします。参加アプリはマイグレーションしません。

```sql
ALTER TABLE "App" ADD COLUMN "defaultPermission" TEXT NULL;
```

既存のアプリは `NULL` のままです。行が無い利用者は、既定を書くまで入れません。既存の `AppGrant` はそのまま有効です。利用者全員への埋め戻しはしません。空文字列は保存せず、既定なしは `NULL` で表します。

`AppGrant.userId` は必須のままです。外部キーと `(userId, appId)` の一意制約は変えません。利用者を削除すると、その利用者の行だけが消えます。アプリを削除すると、そのアプリの行が消えます。既定は `App` の列なので、利用者の増減では変わりません。

## 書くときの検査

管理画面が保存するとき、次だけを受けます。

| 列 | 受け付ける値 |
| --- | --- |
| `App.defaultPermission` | `NULL`、または [grant.md](grant.md) の正の権限 |
| `AppGrant.permission` | 正の権限、または `none` |

`none`、空、一覧に無い文字列は既定に保存しません。正の権限でも `none` でもない値は、行に保存しません。データベースの制約では名前を固定しません。名前を足すときは、保存の検査と [grant.md](grant.md) の一覧を同時に更新します。

## 管理画面と API

管理者は「アプリ」画面で、新規アプリの登録時と既存アプリの編集時に既定権限を選べます。選択肢は次のとおりです。

| UI 表示 | 保存値 | 結果 |
| --- | --- | --- |
| 個別に付与した人だけ | `NULL` | `AppGrant` の行がある利用者だけが利用できる |
| 全利用者に利用者権限 | `user` | 行がない全利用者に `user` を適用する |
| 全利用者に管理者権限 | `admin` | 行がない全利用者に `admin` を適用する |

新規登録フォームでは既定値を暗黙に選ばず、管理者が選択します。既存アプリの編集フォームには現在値を表示し、設定を変えずに他の項目だけを編集した場合も既定値を維持します。`NULL` の値は UI 上で「個別に付与した人だけ」と表示し、API には JSON `null` として送ります。

`admin` を新たに既定に設定するときは、保存前に「個別の例外がない現在および今後の全利用者に管理者権限が適用される」ことを確認します。既定の変更は行がない利用者に対して次のリクエストから反映されます。個別の `AppGrant` がある利用者には既定を適用しません。新しい利用者にも `AppGrant` 行は作らず、設定済みの既定を適用します。

認証サーバー自身の `App` 行は対象外です。`isAuthServer` は永続列にせず、`App.id === authEnv.appId()` から API 応答時に算出します。アプリ一覧では既定を「対象外」と表示して選択欄を出さず、API はその行への `defaultPermission` の設定を拒否します。

管理 API は次の契約にします。

| API | 入出力 |
| --- | --- |
| `GET /admin/apps` | 各アプリに `defaultPermission`（`null` / 現在の正の権限）と `isAuthServer`（`App.id === authEnv.appId()` で算出する boolean）を含めて返す。UI は `isAuthServer = true` の行で既定を「対象外」と表示する |
| `POST /admin/apps` | `id`、`name`、`origin`、`redirectUris`、`defaultPermission` を受け取る。`defaultPermission` は必須で `null` または現在の正の権限一覧のいずれか。認証サーバー自身の ID は登録できない |
| `PATCH /admin/apps/:id` | `defaultPermission` が省略された場合は変更しない。指定時は `null` または現在の正の権限のいずれかを保存する。認証サーバー自身の行への指定は拒否する |
| `GET /admin/grants` | 参加アプリの例外行を返す。各行に `id`、`userId`、`appId`、`permission` を含み、`none` の行も含める。認証サーバー自身の `App.id` の行は返さない |
| `PUT /admin/grants` | `userId`、`appId`、`permission` を受け取る。`permission` は現在の正の権限または `none`。`(userId, appId)` の行がなければ作成し、あれば権限を上書きする（upsert） |
| `DELETE /admin/grants/:userId/:appId` | 例外行を削除し、対象利用者をアプリ既定の判定に戻す。認証サーバー自身の `App.id` に対する作成・更新・削除は拒否する |

既定値と `AppGrant.permission` の正の権限は、[grant.md](grant.md) の正の権限一覧を唯一の正とします。現在の値は `admin` と `user` です。空文字列、既定値への `none`、一覧にない値は `400` で拒否します。`AppGrant.permission` の `none` は個別拒否として受け付けます。認証サーバー自身のアプリへの引き渡しと、そのアプリを対象にした `AppGrant` の作成・更新・削除は拒否し、既定値による入場判定も適用しません。

正の権限を追加するときは、[grant.md](grant.md) の一覧と参加アプリの画面許可に加え、管理 API の入力検証、管理画面の選択肢・表示名、権限の影響を説明する確認文も同じ変更で更新します。新しい権限の既定設定が広い利用者に強い権限を与える場合は、その適用範囲が分かる確認を追加します。

## 引き渡し

`GET /auth/handoff` でセッションを作る条件のうち、付与の確認を実効権限に置き換えます。他の条件は [multi-app-auth.md](https://github.com/czbone/astro-user-webauthn2/blob/main/planning/multi-app-auth.md) のとおりです。

```text
認証サーバーのセッションを検証
Credential が 1 件以上
実効権限が正の権限
redirect_uri が App.redirectUris と完全一致
```

`appId` が認証サーバー自身の `App.id` と一致するときは、実効権限の確認やセッション作成を行わず拒否します。`redirect_uri` のオリジンが認証サーバーと同じ場合も拒否します。認証サーバー自身のアプリへの引き渡しは行いません。

実効権限が付与なしのときは、セッションを作らず、参加アプリへ戻しません。応答は 403「引き渡し先のアプリを利用できません」です。`none` の行がある利用者も、既定が `NULL` で行が無い利用者も、同じです。

セッションの JSON には権限を入れません。

## 既定と例外の操作

アプリの登録時に既定を `NULL` または正の権限に設定します。既定を `admin` にすると、例外行が無い利用者もその参加アプリの管理者になります。

行を作るのは例外だけです。

| 操作 | 結果 |
| --- | --- |
| 既定を `user` にする | 行が無い利用者は利用者になる。次のリクエストから効く |
| 既定を `NULL` に戻す | 行が無い利用者は入れなくなる |
| `admin` の行を一枚作る | その利用者だけ管理者になる |
| `none` の行を一枚作る | その利用者は既定があっても入れない |
| 行を消す | その利用者は既定に戻る。既定が `NULL` なら入れない |
| 利用者を追加する | 行は作らない |
| アプリを追加する | そのアプリの既定を一度決める。既存利用者の行は作らない |

同じ利用者とアプリの組に、行を二枚は作れません。

## 認証サーバーの role

`User.role` は認証サーバー自身の管理操作を認可するロールです。管理画面、ユーザー招待、アプリ登録・編集、`AppGrant` の編集は `role = admin` の利用者だけが行えます。通常の認証操作はログイン状態とパスキー状態で認可し、`role` を参加アプリの実効権限には使いません。参加アプリは `User.role` を参照せず、認証サーバー自身への入場判定にも `AppGrant` を使いません。

seed 管理者の `role = admin` は参加アプリの `admin` を意味しません。既定が `user` の参加アプリには、行が無くても `user` として入れます。
